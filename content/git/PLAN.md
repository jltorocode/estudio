# Git de cero a experto — plan del curso

**Alumno:** hispanohablante (Chile), puede no haber usado nunca una terminal. Quiere llegar a nivel experto. Estudia solo en una plataforma propia donde **todas las prácticas se hacen con Git real** en una terminal de práctica aislada, viendo el **gráfico de commits** y las **tres áreas** en vivo (ver ESQUEMA.md).

**Progresión:** cada sección solo da por sabido lo anterior. Si necesitas algo posterior, no lo uses en ejercicios (o avísalo: «lo veremos en sX»).

**Tono:** claro, cercano, preciso. Primero el **modelo mental** (qué pasa dentro de Git, con diagramas `gitGraph` y de las tres áreas), luego el comando. Errores típicos, buenas prácticas, cómo trabaja un profesional. Nada de relleno. Mensajes de Git en inglés tal cual y explicados.

**Referencias:** documentación oficial (https://git-scm.com/docs — cada comando), el libro **Pro Git 2ª ed.** (https://git-scm.com/book/es/v2 y /en/v2), notas de versión de Git (2.23 switch/restore, 2.28 init.defaultBranch, 2.33 ort, 2.38 --update-refs, 2.40–2.50), GitHub Docs para lo de plataformas, y fuentes reconocidas (Atlassian Git tutorials, blog de GitHub). Git instalado: **2.50.1** (verifica en la terminal lo que afirmes).

## Secciones y alcance

### s01 · Control de versiones, Git y la terminal (`fundamentos`)
Qué problema resuelve el control de versiones (historias de "final_v2_ahora_si.docx"), VCS local/centralizado/distribuido, historia de Git (Linus, 2005, BitKeeper), Git ≠ GitHub, cómo piensa Git (instantáneas, no diferencias; casi todo es local; integridad por hash). Instalación en Windows (Git for Windows/Git Bash), macOS (Xcode CLT, Homebrew) y Linux; `git --version`. **La terminal desde cero**: qué es, `pwd`, `ls`, `cd`, rutas relativas/absolutas, `~`, `mkdir`, `touch`, `cat`, `echo > archivo`, archivos ocultos (`ls -a`). Configuración inicial: `git config --global user.name/user.email`, `init.defaultBranch main`, `core.editor` (p. ej. `"code --wait"`), `--list`, `--show-origin`, niveles system/global/local (breve; a fondo en s13). `git help`, `git <cmd> -h`. Cómo funciona la terminal de práctica de la plataforma (qué admite, `code archivo`, el gráfico y las tres áreas). Ejercicios: navegar y crear estructura de carpetas/archivos, configurar identidad y editor (setup que borra la identidad), consultar configuración.

### s02 · Primer repositorio y las tres áreas (`fundamentos`)
`git init` (y qué es la carpeta `.git`, a vista de pájaro), `git status` (y `-s`), ciclo de vida de un archivo (sin seguimiento, sin modificar, modificado, preparado), **directorio de trabajo → área de preparación (index) → repositorio**, `git add` (archivo, varios, carpeta, `.`, `-A`, patrones), `git commit -m`, commits sin `-m` (el editor; en la plataforma se abre el editor integrado), `git commit -a`, buenos mensajes (imperativo, 50/72, por qué importan), `git log` básico, qué contiene un commit (autor, fecha, mensaje, padre, instantánea). Ejercicios: crear un repo y primeros commits, preparar solo algunos archivos, commits atómicos (separar cambios en dos commits), reparar un status confuso, commit con editor.

### s03 · Ver cambios e historia (`fundamentos`)
`git diff` (trabajo vs preparación), `--staged`/`--cached`, `git diff HEAD`, entre commits y ramas, `--stat`, `--name-only`, `--word-diff`; cómo leer un diff (hunks, +/-). `git log` a fondo: `--oneline`, `--graph`, `--all`, `-p`, `--stat`, `-n`, `--author`, `--since/--until`, `--grep`, `-- ruta`, `--follow`, formatos (`--format`, `--pretty`), rangos `A..B` (intro). `git show`. `git blame` básico. `.gitignore` (patrones, `/`, `**`, negación `!`, por carpeta, global con `core.excludesFile`, plantillas de github/gitignore), `git check-ignore -v`, dejar de rastrear un archivo ya confirmado (`git rm --cached`). `git rm`, `git mv`. Ejercicios: encontrar el commit que introdujo un texto, contar commits de un autor, ignorar archivos (node_modules, .env, logs) correctamente, sacar del repo un archivo sensible ya rastreado sin borrarlo del disco, renombrar conservando historia.

### s04 · Deshacer cambios con seguridad (`fundamentos`)
Mapa mental: qué quiero deshacer y dónde está (trabajo, preparación, último commit, commits locales, commits compartidos). `git restore archivo` y `git restore --staged`, `git restore --source=<commit>`, `git commit --amend` (mensaje y contenido; nunca sobre commits publicados), `git reset` `--soft/--mixed/--hard` (qué mueve cada uno: HEAD/rama, index, trabajo; con diagramas), `git revert` (deshacer creando un commit; historia compartida), `git clean -n/-f/-d/-x`, `git checkout -- archivo` (forma antigua, reconocerla). Árbol de decisión "¿qué comando uso?". Aviso: reset --hard y clean destruyen trabajo no confirmado (reflog en s10). Ejercicios: descartar cambios, sacar un archivo del staging, corregir el mensaje y olvidar un archivo del último commit, deshacer los 2 últimos commits conservando los cambios, revertir un commit ya "publicado", limpiar archivos basura.

### s05 · Ramas (`colaboracion`)
Qué es una rama (un puntero móvil a un commit; crear una rama es gratis), HEAD (puntero a la rama actual), `git branch` (listar, `-v`, `-a`, crear, `-d`/`-D`, `-m`, `--merged/--no-merged`), `git switch` (`-c`, `-`, `--detach`), `git checkout` (forma antigua, reconocerla), qué pasa con los cambios sin confirmar al cambiar de rama, HEAD separado (detached HEAD): qué es, cuándo ocurre, cómo volver y cómo salvar commits hechos ahí, convenciones de nombres (feature/, fix/, hotfix/), ramas de larga vida vs temáticas. Ejercicios: crear y moverse entre ramas, trabajar en paralelo en dos funcionalidades, renombrar master→main, borrar ramas ya fusionadas, rescatar commits hechos en HEAD separado.

### s06 · Fusionar ramas y resolver conflictos (`colaboracion`)
`git merge`: fast-forward vs commit de fusión (fusión de 3 vías, base común `git merge-base`), `--no-ff`, `--ff-only`, `--no-edit`, mensajes de merge. Conflictos: por qué ocurren, marcadores `<<<<<<<`/`=======`/`>>>>>>>`, `git status` durante el merge, resolver editando (`code archivo`), `git add` + `git commit`, `git merge --abort`, `git checkout --ours/--theirs archivo`, `merge.conflictStyle zdiff3` (y diff3), conflictos de borrado/renombrado, estrategias `-X ours/-X theirs`, `git merge --squash`, `git diff` durante un conflicto, buenas prácticas para evitar conflictos. Ejercicios: fast-forward, merge con commit, conflicto sencillo, varios conflictos en varios archivos, conflicto modificar vs borrar, squash merge, proyecto: integrar tres ramas de funcionalidades de un equipo.

### s07 · Repositorios remotos (`colaboracion`)
Qué es un remoto, `origin`, `git remote` (`-v`, `add`, `rename`, `remove`, `set-url`), `git clone`, ramas remotas (`origin/main`) y de seguimiento (upstream), `git fetch` (y `--prune`), `git pull` (= fetch + merge o rebase; `pull.rebase`, `--ff-only`), `git push` (`-u`, push rechazado por non-fast-forward y cómo resolverlo, borrar rama remota `--delete`), `git branch -vv`, ahead/behind, `@{u}`, repos bare (qué son; en la práctica el "servidor" es `~/servidor/*.git`), protocolos (local, HTTPS, SSH) y autenticación (tokens, llaves SSH `ssh-keygen`, agente) explicados con bloques no ejecutables. Ejercicios (con servidor simulado y compañeros con `autor`): clonar, publicar una rama nueva, traer cambios de un compañero, push rechazado y resolverlo, seguir una rama remota existente, limpiar ramas remotas borradas, proyecto: flujo completo de colaboración entre dos "personas".

### s08 · Trabajo en equipo: plataformas, flujos y versiones (`colaboracion`)
GitHub/GitLab/Bitbucket (qué añaden sobre Git), forks y remoto `upstream`, pull requests/merge requests y code review (explicado; se simula el flujo localmente con ramas y servidor), protección de ramas, CODEOWNERS, issues y enlaces, flujos de trabajo: GitHub Flow, Git Flow, trunk-based, ramas de release; Conventional Commits; **tags** ligeros y anotados (`git tag`, `-a`, `-m`, listar, `git show`, `git push --tags`/`origin v1.0.0`, borrar), `git describe`, versionado semántico, releases y CHANGELOG. Ejercicios: sincronizar un fork con upstream (simulado con dos servidores), preparar una rama de PR limpia, etiquetar versiones y publicarlas, flujo release/hotfix de Git Flow, mensajes con Conventional Commits.

### s09 · Rebase y reescritura de historia (`avanzado`)
Qué hace `git rebase` (reaplica commits: nuevos hashes), rebase vs merge (historia lineal vs verdadera), resolver conflictos en rebase (`--continue`, `--skip`, `--abort`), **rebase interactivo** en el editor integrado (`pick`, `reword`, `edit`, `squash`, `fixup`, `drop`, reordenar, `exec`), `git commit --fixup` + `git rebase -i --autosquash` (y `rebase.autoSquash`), `--update-refs` (2.38, ramas apiladas), `git rebase --onto`, `pull --rebase`, **regla de oro** (no reescribir historia publicada), `git push --force-with-lease` (y `--force-if-includes`). Ejercicios: rebase de una rama sobre main, rebase con conflicto, squash de commits WIP, reword de un mensaje antiguo, reordenar y eliminar commits, fixup+autosquash, rebase --onto para mover una rama, actualizar el remoto con force-with-lease tras reescribir.

### s10 · Herramientas de rescate: stash, cherry-pick y reflog (`avanzado`)
`git stash` (`push -m`, `-u`, `--staged`, `list`, `show -p`, `apply`, `pop`, `drop`, `clear`, `branch`), `git cherry-pick` (uno, varios, rangos, `-x`, `--no-commit`, conflictos), **reflog** (qué registra, `git reflog`, `HEAD@{n}`, `rama@{1}`, recuperar commits tras reset --hard, ramas borradas, rebase fallido), `ORIG_HEAD`, `git fsck --lost-found`/`--unreachable`, cuánto dura el reflog (gc). Ejercicios: guardar trabajo a medias para atender un bug urgente, stash de archivos sin seguimiento, llevar un hotfix a otra rama con cherry-pick, recuperar commits perdidos tras reset --hard, resucitar una rama borrada, deshacer un rebase desastroso, proyecto: rescate de un día caótico.

### s11 · Investigar la historia y encontrar errores (`avanzado`)
`git bisect` (start, good, bad, skip, reset, log, `bisect run` con un script de prueba hecho con `code`+`chmod +x`), `git blame` a fondo (`-L`, `-w`, `-C`, `-M`, `--ignore-rev`, `blame.ignoreRevsFile`), pickaxe `git log -S` y `-G`, `git log -L` (historia de una función o de un rango), `git grep` (en el trabajo y en commits), `git shortlog -sn`, `git describe`, `git log --first-parent`, `git range-diff` (comparar versiones de una rama). Ejercicios: encontrar con bisect el commit que rompió un test (manual y con bisect run), descubrir quién y cuándo introdujo una línea, encontrar cuándo desapareció una función, estadísticas de contribución.

### s12 · Git por dentro (`avanzado`)
Objetos: blob, tree, commit, tag anotado; identificados por su hash (SHA-1 y la transición a SHA-256, `--object-format`). Plumbing: `git cat-file -t/-p/-s`, `git hash-object -w`, `git ls-tree`, `git ls-files -s` (el index), `git write-tree`, `git commit-tree`, `git update-ref`, `git symbolic-ref`, crear un commit **a mano** sin porcelana. Refs (heads, tags, remotes), HEAD simbólico, `packed-refs`, objetos sueltos vs packfiles (`git count-objects -v`, `git gc`, `git verify-pack`), deltas, `git fsck`, por qué un commit es una instantánea completa y aun así el repo es pequeño, el DAG. Ejercicios: inspeccionar objetos de un commit, crear un blob y un árbol a mano, construir un commit con plumbing y apuntar una rama a él, encontrar objetos sin referencia, reparar una ref.

### s13 · Configuración, alias, atributos y hooks (`experto`)
Niveles de configuración (system, global, local, worktree), `--show-origin`/`--show-scope`, `includeIf` (identidad distinta por carpeta), opciones útiles (pull.rebase, push.autoSetupRemote, fetch.prune, rerere.enabled, diff.algorithm, merge.conflictStyle, core.autocrlf), **alias** (incluidos los de shell con `!`), `.gitattributes` (`text`/`eol`, `binary`, `diff` drivers, `merge=ours`, `export-ignore`, `linguist-*`), **hooks** con práctica real (`.git/hooks/pre-commit`, `commit-msg`, `pre-push`, `post-commit`; escribirlos con `code` y `chmod +x`; `--no-verify`), `core.hooksPath` y frameworks (pre-commit, Husky) explicados, plantillas (`init.templateDir`), firma de commits con SSH o GPG y credential helpers (explicados sin ejecutar). Ejercicios: configurar alias útiles, identidad por carpeta con includeIf, hook commit-msg que exige Conventional Commits, hook pre-commit que bloquea `console.log`/TODO/secretos, gitattributes para fin de línea y archivos binarios.

### s14 · Repositorios grandes y estructuras avanzadas (`experto`)
`git worktree` (add, list, remove, prune; trabajar en dos ramas a la vez), **submódulos** (add, `update --init --recursive`, `submodule foreach`, actualizar, problemas típicos), `git subtree` (si está disponible en Git 2.50 de macOS; si no, explicado), `sparse-checkout` (cone mode), clonado parcial (`--filter=blob:none`, requiere `uploadpack.allowFilter` en el servidor local) y superficial (`--depth`, `--shallow-since`, `fetch --unshallow`; con `file://`), Git LFS (explicado), monorepos, `git maintenance` y scalar (explicados). Ejercicios: arreglar un bug en otra rama sin guardar el trabajo actual usando worktree, añadir y actualizar un submódulo, clonar un proyecto con submódulos, sparse-checkout de una carpeta, clon superficial y luego completo.

### s15 · Reescritura avanzada, seguridad y mantenimiento (`experto`)
Eliminar un archivo o secreto de TODA la historia: `git filter-repo` (recomendado, se instala aparte; explicado con bloques no ejecutables) vs `git filter-branch` (obsoleto; puede practicarse con `--index-filter` y `FILTER_BRANCH_SQUELCH_WARNING=1` si funciona) y lo imprescindible: rotar la credencial. `git replace`, `git notes`, **rerere** (activar, ver cómo reutiliza resoluciones), estrategias de merge (`ort`, `octopus`, `-s ours` vs `-X ours`), `git bundle` (mover repos sin red), `git archive`, mantenimiento (`gc`, `repack`, `prune`, `maintenance`), verificación de firmas y `fsck`. Ejercicios: purgar un `.env` de toda la historia y verificar que ya no existe, reutilizar resoluciones con rerere, fusionar varias ramas con octopus, transportar un repo con bundle, anotar commits con notes.

### s16 · Git profesional: automatización, CI/CD y casos reales (`experto`)
Scripting con Git (porcelana vs plumbing, `--porcelain`, `git for-each-ref --format`, `git rev-list`, `git rev-parse`, `git status --porcelain=v2`), hooks del lado del servidor (`pre-receive`, `update`, `post-receive` en un repo bare local — ¡practicable!), CI/CD con GitHub Actions (checkout, `fetch-depth`, tags de release; explicado), release engineering (tags firmados, changelogs a partir de commits), **casos de rescate reales**: commit en la rama equivocada, secreto subido, merge equivocado (revertir un merge con `-m 1` y volver a fusionar), historia divergente tras force push de otro, archivos grandes, repo con conflictos eternos; buenas prácticas de equipo, preguntas típicas de entrevistas. Ejercicios: hook pre-receive que rechaza pushes a main sin PR/con mensajes inválidos, script de changelog con for-each-ref/log, 3–4 rescates reales como proyectos.

Ejercicios: 6–8 retos finales integradores de nivel `dificil`. Quiz: **≥ 90 preguntas** con campo `topic` = s01…s16 repartidas por peso (s01 4 %, s02 7 %, s03 7 %, s04 8 %, s05 8 %, s06 8 %, s07 8 %, s08 6 %, s09 8 %, s10 7 %, s11 5 %, s12 6 %, s13 5 %, s14 4 %, s15 4 %, s16 5 %), mucha pregunta de escenario («¿qué comando…?», «¿qué muestra git log --oneline --graph después de…?») verificada en la terminal.
